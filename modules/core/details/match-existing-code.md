# 코드를 쓰기 전에 옆 코드를 읽고 맞춘다

> **같은 패키지의 기존 코드를 먼저 읽고, 그 관례와 용어에 맞춘다.**

일반적인 스타일 가이드보다 그 코드베이스와 맞추는 것이 우선이다.

## 순서 (건너뛰지 않는다)

1. 같은 패키지나 같은 층의 기존 파일을 읽는다. 비어 있으면 가장 비슷한 기능의 파일을 찾는다
2. 이름 짓는 법, 클래스 구조, 도메인 용어, import 순서, 예외 처리, 테스트 쓰는 법을 확인한다
3. 그에 맞춰 쓴다. 다르게 갈 이유가 있으면 그 이유를 PR 본문에 적는다

다른 방식이 더 낫다고 판단돼도 한 파일만 다르게 쓰지 않는다. 바꾸려면 범위를 정해 전체를 바꾼다.

## 같은 개념은 이미 있는 이름으로 부른다

같은 개념에 이름이 둘 생기면 검색이 끊긴다. 이후 작업자는 두 이름이 같은 것인지 매번 확인해야 하고,
그 비용은 코드가 살아 있는 내내 든다.

- 새 이름을 짓기 전에 기존 이름을 찾는다: `git grep -i "<개념>"`
- 식별자 접미사(`no` 와 `id`), 상태 표현, 줄임말도 그 패키지의 관례를 따른다
- 기존 이름이 마음에 들지 않아도 새 이름을 섞지 않는다. 전체 이름 바꾸기를 따로 제안한다

```kotlin
// 기존 코드가 orderBundle / storeNo 를 쓰고 있을 때

// ❌ 같은 개념에 새 이름을 들여온다
class OrderGroupService(private val shopId: Long)

// ✅ 기존 이름을 그대로 쓴다
class OrderBundleService(private val storeNo: Long)
```

## 기계적 강제

`gates` 묶음의 편집 훅은 새 소스 파일을 만들 때, 같은 폴더의 기존 파일을 이 세션에서 한 번도 읽지 않았으면 막는다.
승인을 요구하는 게이트가 아니다. 「읽고 다시 시도하라」고 돌려보낸다.
