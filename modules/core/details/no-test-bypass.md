# 테스트를 끄거나 우회해서 통과시키지 않는다

> **테스트 실패는 원인을 고칠 문제다. 끌 대상이 아니다.**

## 하지 않는 것

- 테스트를 끈다: `@Disabled`, `@Ignore`, `@pytest.mark.skip`, `it.skip`, 주석 처리. 「로컬에 API 키가 없어서」, 「외부 API 라서」도 이유가 되지 않는다
- 일부만 골라 돌리고 전체가 통과했다고 말한다
- 목(mock)이나 하드코딩으로 결과를 맞춘다
- 테스트 전용 설정 파일이나 프로파일을 새로 만들어 실패를 피한다
- 기능을 꺼서 문제를 피한다

## 실패했을 때 하는 것

1. 로그와 스택 트레이스로 원인을 정확히 찾는다
2. 원인에 맞게 고친다
   - 코드 버그 → 코드를 고친다
   - 설정 오류 → 설정을 바로잡는다
   - API 키가 없다 → 사용자에게 알리고 설정 방법을 안내한다
3. 전체 테스트를 다시 돌려 모두 통과하는지 확인한다

작업을 마치면 프로젝트의 전체 통합 테스트도 실행한다. 외부 시스템과 연동하는 기능은 실제 연결로 검증한다.
가짜 입력이나 mock을 쓰는 단위 테스트가 통과해도 실제 연동까지 확인했다고 말하지 않는다.
접근 권한이나 실행 환경이 없어 통합 테스트를 돌릴 수 없으면, 수행한 검사와 아직 검증하지 못한 범위를 나눠 보고한다.

## 이유

실패하는 테스트를 끄면 그 순간 초록불이 켜진다. 그 초록불은 코드가 맞다는 뜻이 아니다. 아무도 확인하지 않았다는 뜻이다.
테스트를 끈 커밋은 리뷰에서도 잘 안 보인다. 그래서 `gates` 묶음의 편집 훅이 테스트 파일에 끄는 표시가 새로 붙는 것을 막는다.
