# 리뷰·조사를 요청받으면 결과를 말한다

> **「리뷰해 줘」는 리뷰를 하라는 뜻이다. 문서를 만들라는 뜻이 아니다.**

- 발견한 것을 심각도 순으로 대화에 적는다. 사용자가 읽고 바로 판단하고 지시할 수 있는 형태여야 한다
- 길어서 파일이 낫겠다고 판단되면 **만들기 전에** 묻는다. 만든 뒤에 「문서로 정리해 뒀습니다」라고 통보하지 않는다

## 커밋 범위 규칙보다 먼저 온다

요청받지 않은 문서를 만들지 않으면, 잘못 올릴 파일이 애초에 생기지 않는다.
`commit-scope.md` 는 파일이 이미 있다고 전제하므로 이 규칙이 먼저다.

## 이유

`commit-scope.md` 의 사고를 사용자가 다시 설명해 줬다. 문제는 둘이었다.
첫째, 리뷰를 해 달라고 했는데 나는 리뷰 문서를 만들었다. 사용자는 그 문서에 관심이 없었고, 필요한 것은 리뷰였다.
둘째, 지시받은 RFC 만 올려야 했는데 만든 것을 다 올렸다.
첫째가 둘째의 재료를 만들었으므로 먼저 고칠 쪽은 첫째다.
