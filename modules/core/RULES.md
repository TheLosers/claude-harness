# 기본 규칙

어느 프로젝트에서나 지킨다. 규칙마다 한 줄이다.
적용이 애매하면 괄호 안의 파일을 읽고 판단한다. 파일마다 이 규칙을 만든 사고가 적혀 있다.

1. **사용자가 물으면 대답만 한다.** 실행은 사용자가 정한다. 「하지 마」는 사용자가 풀 때까지 살아 있다. ([이유](details/answer-only.md))
2. **조사와 진단은 증거로 끝낸다.** 증상이 한 번 안 보인 것, 「됐다」는 말은 끝낼 근거가 아니다. ([이유](details/evidence.md))
3. **지목받은 것만 커밋하고 푸시한다.** `git add -A` 를 쓰지 않는다. 내가 만든 산출물은 기본이 로컬이다. ([이유](details/commit-scope.md))
4. **리뷰·조사를 요청받으면 결과를 그 자리에서 말한다.** 문서 파일이 필요해 보이면 만들기 전에 묻는다. ([이유](details/review-is-not-a-document.md))
5. **머지와 PR 리뷰 등록은 매번 승인받는다.** 「완료되면」「이어서 해줘」는 허가가 아니다. ([이유](details/merge-approval.md))
6. **테스트를 끄거나 우회해서 통과시키지 않는다.** 실패는 원인을 고칠 문제다. ([이유](details/no-test-bypass.md))
7. **코드를 쓰기 전에 옆 코드를 읽고 맞춘다.** 같은 개념은 이미 있는 이름으로 부른다. ([이유](details/match-existing-code.md))

8. **개발 전에 사용하는 버전의 공식 문서를 읽는다.** 이미 제공되는 기능을 다시 만들지 않는다. ([이유](details/official-docs.md))
9. **지금 호출되지 않는 함수를 미리 만들지 않는다.** ([이유](details/minimal-implementation.md))
10. **작업을 작고 검증 가능한 단위로 나누고, 하나 끝날 때마다 테스트한다.** ([이유](details/todo.md))

이 규칙은 개인 작업 기준이다. 프로젝트의 권한·보안 정책을 완화하는 근거로 쓰지 않는다.
