# 왜 차단과 승인 표식을 나눴나

원래 사용 환경에서는 권한 확인을 건너뛰는 모드를 썼다. 그 환경에서 `ask`가 확인창 없이 통과하는 것을 관찰했다.
그래서 해당 명령을 `deny`로 멈추고, 실제 승인 이후에만 표식을 확인해 한 번 통과시키는 방식을 택했다.
다른 버전이나 권한 모드의 동작까지 이 관찰로 단정하지 않는다.

## 승인 순서

1. 대상과 실행할 내용을 사용자에게 보인다. DB 쓰기는 SQL 전문과 환경, PR은 번호와 내용, 브라우저 종료는 대상 프로세스를 밝힌다.
2. 사용자 승인을 받는다.
3. 훅의 차단 메시지에 나온 경로와 형식으로 승인 표식을 만든다.
4. 같은 명령을 다시 실행한다. 훅이 표식을 소비하면 다음 실행은 새 승인이 필요하다.

표식의 기본 유효 시간은 10분이다. 설정에 따라 달라질 수 있다.
운영 DB 차단은 승인 표식으로 해제하지 않는다.

## 표식이 보장하지 않는 것

표식은 대화를 읽어 사용자가 승인했는지 확인하지 못한다. 에이전트가 승인 없이 표식을 만들면 보호가 무너진다.
실제 승인을 먼저 받는 책임은 규칙에 남아 있다. 대상 문자열을 확인하는 방식도 명령 전체의 의미를 검증하지 않는다.

훅은 명령문의 패턴을 검사하므로 놓치는 명령과 잘못 차단하는 명령이 생길 수 있다.
훅이 통과시켰다는 이유로 실행 권한을 얻었다고 판단하지 않는다.
권한 제한, 자격 증명 관리, 조직의 승인 절차는 별도로 필요하다.
