# 실행 전 확인 규칙

규칙으로 판단 기준을 두고, [Bash 훅](hooks/bash-guard.sh)과 [편집 훅](hooks/edit-guard.sh)으로 일부 실수를 감지한다.
훅은 모든 명령을 해석하는 보안 경계가 아니다.

1. **승인이 필요한 명령은 먼저 내용을 보이고 승인받는다.** 승인 표식은 실제 승인을 대신하지 않는다. ([절차와 한계](details/why-deny-and-marker.md))
2. **훅이 막으면 우회하지 않는다.** 차단 이유를 확인하고 필요한 승인이나 선행 확인을 마친다.
3. **사용자가 쓰는 브라우저를 임의로 종료하지 않는다.** 연결 실패를 반복하지 않고, 내가 연 탭만 정리한다. ([이유](details/browser.md))
4. **회사별 주소와 허용 범위는 저장소 밖 설정에 둔다.** [설정 예시](gates.conf.example)에 실제 주소를 넣어 커밋하지 않는다.

| 확인 대상 | 동작 |
|---|---|
| DB 쓰기 | 감지한 DDL/DML에 승인 표식을 요구한다 |
| 운영 DB | 설정한 주소가 감지되면 조회도 차단한다. 주소 설정이 비어 있으면 이 검사는 꺼진다 |
| PR 리뷰 등록·머지 | 감지한 명령에 승인 표식을 요구한다 |
| 브라우저 종료 | 브라우저를 대상으로 감지한 종료 명령에 승인 표식을 요구한다 |
| 푸시 | 파일 목록을 알려 준다. 푸시 자체를 차단하지 않는다 |
| 소스 편집 | 테스트 비활성화 표시의 추가, 새 파일 작성 전 기존 코드 열람 여부를 검사한다 |
