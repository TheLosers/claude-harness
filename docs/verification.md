# 검증 범위와 남은 한계

## 재현하기

```bash
python3 -m unittest discover -s tests -p 'test_*.py' -v
bash tests/test-public-scan.sh
bash -n modules/gates/hooks/bash-guard.sh
bash -n modules/gates/hooks/edit-guard.sh
bash -n scripts/check-public.sh
```

공개 준비 시 macOS의 Bash 3.2와 jq, Python 3에서 훅 테스트 32개와 검사기 테스트 8개를 통과했다. 테스트는 임시 설정·표식·로그를 사용한다. 입력 JSON 안의 DB·GitHub·프로세스 종료 명령은 문자열로 검사할 뿐 실행하지 않는다. 검사기 테스트용 임시 Git 저장소도 종료 시 정리한다.

ShellCheck는 검증 환경에 설치되지 않아 실행하지 않았다. Linux와 Claude Code 안에서의 통합 시험은 아직 수행하지 않았다. 테스트 수는 성능이나 사고 감소율을 뜻하지 않는다.

## 공개 준비 중 수정한 것

| 재현한 문제 | 수정과 회귀 검사 |
|---|---|
| 잘못된 JSON 또는 jq 누락 시 통과했다 | exit 2로 중단하도록 바꾸고 두 훅 모두 검사한다 |
| 하나의 승인 표식을 확인하면 뒤에 남은 게이트를 검사하지 않았다 | 다음 검사도 실행하며 DB 쓰기 뒤 머지, 리뷰 뒤 머지 등을 검사한다 |
| JSON의 공백 때문에 기존 코드 읽기 기록을 놓쳤다 | JSON 구조로 확인하고 같은 폴더와 하위 폴더를 구분한다 |
| 숫자 표식의 내용이 정규식으로 해석될 수 있었다 | 숫자 형식을 검사한다 |
| 공개 검사기의 경로 모드에서 빈 배열을 처리하지 못했다 | 공개판의 경로 모드는 제외 배열 없이 `.git`만 제외한다 |
| 파일에서 지운 값이 이력에는 남을 수 있다 | 커밋별 파일을 검사하고 삭제 전 값을 감지하는 테스트를 둔다 |

## 의도적으로 남은 경계

- **문자열 검사다.** 셸 변수·별칭·간접 실행·SQL 파일·다른 DB 도구로 실행하는 작업을 모두 잡지 못한다.
- **승인 표식은 인증 수단이 아니다.** 에이전트도 만들 수 있다. 승인 후에도 한 번에 한 대상의 단일 명령만 실행해야 한다. 같은 게이트의 여러 작업을 한 명령으로 묶으면 대상을 정확히 구분하지 못한다.
- **편집 검사 범위가 좁다.** `Edit|Write` 훅은 Bash나 다른 도구로 파일을 쓰는 동작을 검사하지 않는다. 비활성화 패턴의 줄 수 비교는 테스트를 무력화하는 모든 변경을 알아내지 못한다.
- **읽기 기록은 이해의 증거가 아니다.** Read 호출 기록이 있어도 파일을 성공적으로 읽었거나 내용을 이해했다고 보장할 수 없다.
- **로컬 로그에도 정보가 남는다.** 명령 앞부분과 작업 경로가 기록된다. 비밀값을 명령줄에 넣지 않고 로그를 외부에 공유하지 않는다.
- **공개 검사도 완전하지 않다.** 알려진 패턴과 개인 금지어를 찾는 도구다. 미등록 고유명사나 다른 형식의 비밀값, 바이너리 파일은 별도로 확인해야 한다.

이 제약 때문에 최소 권한의 계정, 별도 승인 절차, 필요한 환경의 샌드박스를 함께 사용한다. 훅이 통과했다는 사실만으로 실행 허가나 공개 안전성을 판단하지 않는다.
